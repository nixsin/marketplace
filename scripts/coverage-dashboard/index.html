Raw data: api-history.json · web-history.json · lighthouse-history.json · accessibility-history.json. Coverage only appends when the corresponding CI job actually runs (path-filtered — see this repo's CLAUDE.md), so gaps mean "unchanged," not "missing." Lighthouse appends on every push-to-main run of that job regardless of pass/fail, so a real regression shows up here rather than being hidden. Accessibility is a hybrid of the two: it's genuinely skipped (gap, not failure) on pushes that don't touch the web app or dependencies, but whenever it *does* run, a real violation still appends and shows up rather than freezing the badge at the last passing value.
